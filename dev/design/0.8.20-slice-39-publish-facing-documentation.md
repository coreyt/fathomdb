# Publish-facing documentation — design of record (0.8.20 Slice 39, `R-20-DOC`)

**Requirement id: `R-20-DOC`.** Minted by the Steward 2026-07-30 (`seq-194`) under the HITL directive
to get project / `dev/` / `docs/` documentation **not stale** before the first real publish since
0.8.9, and under the **MIT license ruling** (`seq-193`).

Slice 39 runs **before** Slice 40 (`R-20-PUB`). That ordering is mechanical, not editorial:
`scripts/verify-release-gates.sh` **check 4 hard-fails** unless `CHANGELOG.md` carries a heading
matching the version being released, and no `## 0.8.20` section exists. Slice 40's
`workflow_dispatch` rehearsal therefore cannot pass until this slice lands.

---

## 1. Problem

A publish-facing survey of what the registries would actually receive — conducted by **running**
`cargo package --list`, `npm pack --dry-run` and reading a built wheel's `METADATA`, not by
inspection — found four classes of defect. Two are irreversible once a tag is pushed, because
crates.io versions are immutable.

| # | Defect | Blocking? |
|---|---|---|
| 1 | The repo-root `LICENSE` is **MIT**; all four publishable manifests declare **Apache-2.0**; **no artifact ships a license file at all** | **Yes — irreversible** |
| 2 | No `## 0.8.20` CHANGELOG section; the largest consumer-visible break is undocumented; one shipped line is factually wrong | **Yes — gate check 4** |
| 3 | Registry surfaces are near-empty: no README on 7 crates or npm; the PyPI page is a 12-line internal stub linking files that do not ship | No, but it is the release's first impression |
| 4 | `docs/`, `dev/interfaces/` and several doc-comments describe a surface two releases old | No — the docs site is not deployed |

---

## 2. The license decision, and why the *shipping* half is the hard part

The **type** question is settled: **MIT** (`seq-193`). Correcting four manifest fields is mechanical.

The **shipping** question is not settled, and is the reason this document exists. A license file must
appear in the artifact for **ten** published units: 7 crates, the wheel, and both npm packages. Each
packaging tool decides inclusion differently, and one of them cannot reach the repo root at all.

**Constraint that shapes every option:** `cargo package` refuses to include paths outside the package
root. `include = ["../../../LICENSE"]` does not work. So a repo-root file cannot simply be referenced
by the crates.

### Candidate mechanisms — to be MEASURED, not assumed

These are hypotheses. **Do not select one from this list and implement it.** Each must be verified by
running the packaging command and reading the resulting file list.

- **(a) A copy of `LICENSE` in each crate directory.** Reliable for Cargo; costs 7 duplicate files
  that can drift.
- **(b) A symlink per crate.** Cargo's treatment of symlinks at package time is the open question —
  whether it stores the link or the content. Measure it; do not reason about it.
- **(c) Tool-native license metadata.** `license-file` in Cargo, `license-files` in `pyproject.toml`,
  npm's automatic inclusion of a root `LICENSE` **regardless of the `files` allowlist**. Each is
  plausible; each has version-dependent behaviour.

**Whatever is chosen, the acceptance evidence is identical: the packaging command's own file list.**
This is the same method that found the defect, and it is the only method that cannot be satisfied by
a plausible-looking configuration change.

### The guard is part of the deliverable

This drift persisted silently across the entire 0.8.x line — a manifest and a file disagreeing, with
nothing to notice. Per standing policy, **when something slips a guardrail, fix the tooling so it
cannot recur for anyone**, rather than recording an intention to be careful.

Ship a check asserting (i) the repo `LICENSE`'s type matches every publishable manifest's `license`
field, and (ii) a license file is present in each packaged artifact. **It must be proven non-vacuous
with a control** — deliberately break one field, show the check fails, restore. A canary in this same
release passed loudly while hashing nothing on both sides; a check that cannot fail is worse than no
check, because it is read as coverage.

⚠ Wiring it into CI requires `.github/`, which is **Slice 40's exclusive territory** this release.
Ship the script and hand the wiring to 40. Registering it in `scripts/agent-test.sh` is in bounds —
`seq-172`'s CI prohibition was scoped to the sbom-survey suite and does not reach this.

## 3. CHANGELOG — derived, never invented

The span is 0.8.9 → HEAD across eleven micro versions, and **no 0.8.10–0.8.19 sections exist**, so
this one section is everything a consumer stepping between published versions will read.

Four named defects, each verified:

1. **`SearchHit.id` `u64` → `IdSpace` is absent entirely** — `grep -n IdSpace CHANGELOG.md` returns
   nothing. It is the largest consumer-visible break in the pair. It landed in 0.8.19 as C-2.
2. **`CHANGELOG.md:160` says "Schema version 20 → 21".** `SCHEMA_VERSION` is **24**; 0.8.9 shipped
   **15**. The real span is **15 → 24**.
3. **Migration step 23 destroys all edge data with no warning** — `fathomdb-schema/src/lib.rs:751`:
   *"existing edge rows do NOT survive… no stored ISO-8601 value is converted"*, plus a
   `DELETE FROM search_index_edges`. An in-place upgrade loses edges.
4. **`TC-56`** — a shipped `Engine::drain` behaviour change the ledger says this changelog must carry.

`CHANGELOG.md:5-7` makes a `### Removed` heading a merge-gated invariant for released sections.

**Derive content from git and the landed plan docs.** Where consumer-visibility cannot be
established, **say so in the closure report rather than writing a confident line**. Defect 2 above is
already an instance of a wrong entry shipping; a thin section is recoverable, a false one is not.

## 4. Scope boundary

**In:** `license` fields, license shipping + its guard, the CHANGELOG section, registry READMEs and
crate-level docs, **crate `keywords`**, `docs/` currency, `dev/interfaces/*.md` (**TC-39**), and
doc-comments that contradict shipped behaviour (notably `PreparedWrite::Node.valid_until`, which names
`EngineError::InvalidArgument` where the code returns `WriteValidation`).

### Registry metadata — keywords in, categories out (HITL `seq-198`)

**`keywords` are Slice 39's**, and this document is their owning record — they appear in no other plan
or requirement. Constraint: **max 5, each at most 20 characters**. They are validated locally by
`cargo package`, so a mistake fails before anything leaves the machine.

⛔ **`categories` are OUT of 0.8.20**, re-entered at 0.8.21 to be ready for the 0.8.22 publish. Slug
values are validated **server-side only at real publish** — mid-tier, after earlier crates have
already uploaded **immutably**. That is the v0.8.9 partial-publish shape, and discoverability does not
justify risking a wedged half-published release on the first publish in a year.

**Out, and deliberately:**

- **Any `version` field.** The `0.8.9 → 0.8.20` bump is Slice 40's, including the undecided **Axis-E**
  call. `src/python/fathomdb/__init__.py:73` still reads `0.6.0` — **note it for 40, do not fix it.**
- **Anything in `.github/`** — Slice 40's exclusive territory this release.
- **The governed surface.** `check-governed-surface-pin.sh` stays rc=0. Do not edit
  `src/conformance/governed-surface-allowlist.json`: where its `_comment` reads
  `AWAITING HITL SIGN-OFF, NOT SIGNED`, that literal is load-bearing for the T1e byte pin and its
  correction is deliberately deferred to the Slice 40 mint.
- **Schema** (stays 24) and **eu7** (zero runs, any backend, any N — F-28, closed by decision).

## 5. Acceptance

**No AC is minted and no new `R-20-xx` id beyond `R-20-DOC`** — gate by test name and by the §2 guard.

1. All four manifests read MIT and agree with the repo `LICENSE`.
2. A license file appears in the artifact file list for **all ten** published units, evidenced by the
   packaging commands' own output.
3. The license-consistency guard exists, passes, and **fails under a control**.
4. `CHANGELOG.md` has a `## 0.8.20` section carrying items 1–4 of §3 and a `### Removed` heading;
   `scripts/verify-release-gates.sh` check 4 is satisfiable.
5. Every crate and npm package has a README; the PyPI `long_description` is consumer-facing and links
   only to things that ship. Every publishable crate carries `keywords` (≤5, each ≤20 chars) and
   **no** crate carries `categories`.
6. No `docs/` page instructs installing 0.6.0; every write example includes the mandatory `source_id`.
7. `TC-36` closed: no published API doc declares `SearchHit.id` as `int` / `number`.
8. Full-workspace `cargo clippy --workspace --all-targets` **and** `cargo check --workspace
   --all-targets` both exit 0; `mkdocs build --strict` exits 0 if `docs/` was touched.
