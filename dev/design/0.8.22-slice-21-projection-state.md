# Slice 21 — Projection runtime-state design

## Intent

`DenseReadiness` currently derives only from outstanding projection work. A
durable vector declaration in a session without `runtime_embedder` can therefore
read `ready` even though that session cannot create vectors. The status must
distinguish unavailable runtime from completed runtime work, and a later safe
embedder open should repair the eligible stranded work without a redundant
`configure_projections` call.

## F5 decision and C1 contract gate

Before implementation, record this HITL-authorized decision through the
steward ledger and amend the byte-pinned OPP-12 C1 contract, its re-derived
conformance pin/checker/tests, the governed-surface commentary, all interfaces,
and all public type/doc surfaces:

> `DenseReadiness` is `{unavailable, embedding, ready}`. For a declared vector
> projection, `unavailable` means no usable dense runtime (absent or
> equivalence-refused); `embedding` means usable runtime with eligible
> outstanding work; `ready` means usable runtime with that work quiescent.
> `pending` remains admission-only. Readiness is engine-set, accept-inert
> metadata. `drain` remains a passive barrier: successful drain implies `ready`
> only with a usable dense runtime. Boot graft is permitted only after identity
> and equivalence acceptance, commits enrolment/requeue atomically before
> notification, and never reopens `failed` terminals.

The C1 pin must be fully re-derived under review. Editing a hash or an
interface document without this contract amendment deliberately fails
conformance and is not an implementation shortcut.

## State contract

For a declared vector projection, the derived state is:

| Runtime embedder | Outstanding eligible work | State |
| --- | --- | --- |
| absent or not safety-approved | any | `unavailable` |
| present and safety-approved | yes | `embedding` |
| present and safety-approved | no | `ready` |

The state remains corpus-wide because the shipped dense pipeline is corpus-wide.
It is derived on read and stored nowhere. `None` remains the correct value for
a projection with no vector declaration. A usable dense runtime is exactly an
attached runtime embedder whose vector-equivalence guard has not refused dense
work; every scheduling/read path uses this one predicate.

For a declared vector projection, a successful `drain()` only implies `ready`
when a usable dense runtime is live and the shared work predicate is quiescent.
A fresh no-runtime declaration may correctly drain with no work while the
derived state remains `unavailable`. An already-enrolled no-runtime session may
instead time out while durable work remains, but its derived state is still
`unavailable`. The Rust, Python, and TypeScript public contracts and their
existing pins must be amended together.

Adding an enum member is additive at the producer wire shape but can break an
external exhaustive consumer. It is therefore a signed public semantic change,
not a cosmetic type update.

## Safe boot graft

The repair reuses the declared-vector enrolment and stranded-row recovery
mechanisms, but not their unsafe call placement. The implementation must:

1. finish schema, identity, and vector-equivalence safety checks first. For an
   otherwise-unregistered declared vector arm, run a prospective-arm preflight
   before any graft mutation, scheduler construction, dispatch, or notification;
   a necessary open-path refactor is in scope;
2. when a live approved runtime and a vector declaration exist, begin one writer
   transaction;
3. enrol only committable kinds, reopen only stranded `up_to_date` terminals
   without vector rows, and rewind only as the existing recovery algorithm
   requires;
4. commit; then construct/notify the projection runtime; and
5. leave the database unchanged when the runtime is absent, disabled, rejected,
   or there is no eligible work. This prohibits new boot-graft/enrolment work;
   it does not erase or pretend away already-enrolled durable work.

This ordering prevents a rejected/divergent embedder from writing new vectors,
and makes crash recovery converge to either pre-graft state or a durable,
truthful pending state. `failed` terminals remain terminal. The existing
duplicate-embed and scheduler tests are regression guards, not evidence that a
new boot path is automatically safe.

## TDD proof plan

RED tests precede each implementation phase:

1. engine readiness tests for every table row above and the two superseded
   vacuous-ready fixtures, including fresh no-runtime no-op `drain()` and
   already-enrolled no-runtime timeout behavior;
2. boot-graft tests that inspect terminal/vector tables before and after open,
   then assert `embedding → ready` and exactly-once embedding after `drain`;
3. a divergent-embedder fixture seeded with a previously accepted baseline,
   proving prospective-arm refusal occurs before enrolment, terminal/vector
   writes, scheduler dispatch, or notification; plus negative tests for absent
   runtime, failed terminal, and repeated opens; and
4. Python/TypeScript boundary and functional tests for `unavailable`, exact
   literal parity with an exported Python alias, and the read→configure no-op
   round trip.

The old re-apply graft fixture is renamed and retained as proof of the second
repair door; it must not keep a stale name or comment after boot graft exists.

## Documentation scope

Update all three interface documents and public type/docstring surfaces. They
must distinguish engine-set readiness from caller input, explain why `built`
and `deferred` are not mutually exclusive, qualify `drain() → ready`, and
reserve `pending` for the admission axis. Python exports a
`DenseReadiness = Literal["unavailable", "embedding", "ready"]` alias in both
runtime typing and its stub. The OPP-12 amendment and its re-derived C1
conformance artifact precede RED implementation tests.
