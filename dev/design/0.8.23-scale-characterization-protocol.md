# 0.8.23 scale-characterization protocol

## Purpose and boundary

This protocol pre-registers how 0.8.23 will characterize the scale behavior of
the shipped FathomDB exact-search stack. It is a measurement protocol and
result-artifact contract, not a benchmark result, a performance threshold, or a
supported-scale statement.

Slice 17 records no measurements. Execution is deferred until the complete
0.8.22 dependency stack, including the coupled rusqlite and sqlite-vec
migration, is the candidate under test. A later 0.8.23 execution may produce a
fixture-scoped characterization only; it cannot by itself establish the firm
supported-scale outcome reserved for 0.8.24.

This protocol characterizes the shipped exact stack. It does not authorize an
ANN, HNSW, IVF, partition-key, or other index implementation path; ANN/HNSW
remains a 2.x design decision. It does not change existing 10k gates or treat
their historical 100k/1M observations as a supported-scale envelope.

## System under test and fixture

The system under test is the production Engine::search read path exercised by
src/rust/crates/fathomdb-engine/tests/perf_gates.rs::ac_013_vector_retrieval_latency.
It invokes FTS5 plus the shipped two-phase sqlite-vec vec0 vector arm: binary
bit-KNN candidate generation, f32 reranking, and the normal fused search path.
It is not an isolated popcount microbenchmark, direct SQL probe, mocked
database, or alternative index.

The required fixture is the deterministic AC-013 synthetic vector fixture:

| Field | Required value / capture |
| --- | --- |
| fixture_id | ac013-deterministic-vector-v1 |
| Generator | seed_ac013_corpus in perf_gates.rs |
| Corpus seed | 0x0AC0_13D0_13D0 |
| Query generator and seed | ac013_query_bodies; 0x0AC0_130D_EC0D_E000 |
| Source identity | test:fixture |
| Vector dimension | 384 via AC013_VECTOR_DIM=384, matching the shipped default BGE dimension |
| Query count | 1,000 held-out generated queries per repetition (PERF_SAMPLES) |
| Scale points | 10,000, 100,000, and 1,000,000 indexed rows |

The executor records the Git blob ID of perf_gates.rs at the measured candidate,
each literal above, the resolved row count, and a SHA-256 of a canonical JSON
rendering of this descriptor. A mismatch is an environmental invalidity, not a
new fixture version. Changing a descriptor field requires a new fixture_id and
an explicit protocol revision before a result is valid.

This fixture is synthetic and capacity-oriented. A valid result says only how
this exact production path behaved with this fixture on the captured
environment. It does not make an IR-relevance, real-corpus, or all-workload
claim.

## Candidate and environment provenance

Before timing, the executor must capture all of the following:

| Evidence | Required capture |
| --- | --- |
| Candidate | Full Git SHA, branch/ref, commit timestamp, git status --porcelain, and a clean-worktree assertion. A dirty candidate is invalid. |
| Dependencies | SHA-256 and Git blob ID of Cargo.lock; locked rusqlite, sqlite-vec, and libsqlite3-sys versions; cargo metadata --locked --no-deps output or digest. |
| Schema/build | SCHEMA_VERSION, schema-source blob ID, rustc -Vv, cargo -V, target triple, profile, enabled features, full command, and SQLite version from the built process. |
| Fixture | The descriptor/hash above and the perf_gates.rs blob ID. |
| Host | JSON from scripts/perf-experiments/collect-host-spec.sh, RAM total/available, database-volume filesystem/free-space, and CPU governor/frequency policy where available. |
| GPU | nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv,noheader when available; otherwise explicit not_present_or_unavailable. GPU is not a retrieval accelerator here, but its state is provenance. |
| Isolation | Timestamp, process/load evidence, no concurrent benchmark workload, and any CPU affinity, governor, power, container, or virtualization setting. |

collect-host-spec.sh remains the base host convention. The 0.8.23 executor may
extend the existing performance-runner capture in place for the additional RAM,
GPU, and isolation fields; it must not introduce a second benchmark framework
or authority index.

The executor must also record the complete 0.8.22 release-state candidate SHA
and its Slice 5 dependency evidence. If that closure is absent or names a
different stack, report MISSING_PREREQUISITE and do not characterize scale.

## Run matrix

For each scale point, perform at least five independent repetitions of each
treatment. Every repetition uses a newly seeded database and process. Record
seed/write, embedding, and projection-drain time separately from query latency.
The 1,000 held-out queries do not change across repetitions.

| Treatment | Procedure | Meaning |
| --- | --- | --- |
| process_cold | Fresh process and newly seeded database; measure the first query without a query warmup. | Cold application/engine state only; never label it OS-page-cache cold. |
| warm | On that database, run the full held-out suite once and discard it; measure a second full suite. | Existing AC-013 warm-cache convention. |

Query concurrency is one. AC-019 may be recorded separately with the same
fixture, but it must not be pooled with AC-013 single-query values. The existing
scripts/perf-experiments/run-experiment.sh, run-ac013.sh, and
collect-host-spec.sh are the execution starting point. The future executor must
extend that runner/artifact path for repetitions and treatments, run with
AGENT_LONG=1 and AC013_VECTOR_DIM=384, and record the complete command.

## Metrics and summaries

Each repetition records indexed rows, accepted writes, vector-row count after
drain, drain outcome, first-query latency, all 1,000 warm query samples or a
lossless reproducible histogram, p50/p95/p99/min/max/mean, setup durations,
result counts, query errors/timeouts/skips/invariant failures, exit status, and
raw-log paths with SHA-256 digests.

For every (scale_point, treatment) cell, report the repetition-level
percentiles and their median, minimum, and maximum. Do not pool samples across
repetitions and call the result a five-run characterization. No numeric
threshold is introduced: a valid characterization may show poor latency.

## Result artifact contract

A future result is a versioned JSON artifact at
dev/plans/runs/0.8.23-scale-<candidate-sha>-output.json. It reuses the existing
performance closure convention but has this top-level contract:

~~~json
{
  "schema_version": 1,
  "protocol": "0.8.23-scale-characterization-v1",
  "status": "DEFERRED|MISSING_PREREQUISITE|INSUFFICIENT_SAMPLES|ENVIRONMENT_INVALID|CHARACTERIZED",
  "claim_scope": "fixture_scoped_exact_search_characterization",
  "candidate": {"head_sha": "...", "worktree_clean": true, "schema_version": 0},
  "fixture": {"id": "ac013-deterministic-vector-v1", "descriptor_sha256": "..."},
  "environment": {"host": {}, "gpu": {}, "isolation": {}},
  "matrix": [{"rows": 10000, "treatment": "warm", "repetitions": []}],
  "integrity": {"raw_log_digests": [], "invalid_reasons": [], "missing_prerequisites": []},
  "summary": null,
  "next_step": "..."
}
~~~

matrix contains per-repetition metrics and non-pooled summaries. The artifact
never replaces a missing number with zero, an empty array with a passing
percentile, or an unavailable GPU value with an invented device.

## Status rules

| Status | Required condition | Prohibited interpretation |
| --- | --- | --- |
| DEFERRED | Protocol only; no timing attempted. | A measurement or passing result. |
| MISSING_PREREQUISITE | Required release closure, fixture, runner capability, toolchain, or capture is absent; name each item. | Missing input as zero, skip, or pass. |
| INSUFFICIENT_SAMPLES | Any cell has fewer than five completed repetitions or fewer than 1,000 warm queries per completed repetition. Preserve partial evidence. | Partial data as a characterization. |
| ENVIRONMENT_INVALID | Candidate/fixture/lock mismatch, dirty worktree, failed drain/vector invariant, query error/timeout, contamination, missing provenance, or invalid command/profile; name reasons. | Omitting the reason to make a retry valid. |
| CHARACTERIZED | All prerequisites/capture are present, every cell meets sample requirements, integrity checks pass, and raw evidence remains. | A threshold pass, scale-limit promise, or 0.8.24 firm claim. |

Only CHARACTERIZED permits a non-null summary. It remains a fixture-scoped
measurement readout, not a release approval. A later decision must cite this
artifact and its scope rather than infer an envelope from status alone.
