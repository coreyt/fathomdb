## 1. Problem

`scripts/agent-test.sh` runs under `set -euo pipefail` and **stops at the first failing suite**. It
registers **31 suites**; the abort currently lands at `test-check-governed-surface-pin`
(`agent-test.sh:73`), which leaves **23 suites registered after it that have never run in a full pass.**

Two consequences, both already measured in this release:

- **The aggregate exit code is a vacuous signal** (**TC-16**). It says nothing about the Rust or Python
  steps because control never reaches them.
- **Red suites are discovered one at a time, late.** Slice 40's brief said one suite was red; the true
  count was four. Nobody knows the state of the other 23.

The same shape recurs *inside* individual scripts. `scripts/tests/test_actionlint_fixture.sh:56`
`exit 1`s on the first failing tier of a `t1..t7` loop, which is exactly why only `t1` ever surfaced
and a **second independent defect stayed hidden** behind it for six minor versions.

---

## 2. The design question, and the failure mode to avoid

Converting fail-fast to continue-on-failure is **not** the same as making failures non-fatal, and
conflating the two would be worse than the current behaviour.

> ### ⛔ The invariant
>
> **A run that had any failure MUST still exit non-zero.** Continue-on-failure changes *when* the
> harness stops — not *whether* a failure counts. Turning a gate into a warning would manufacture a
> vacuous green across the entire suite, which is the single defect class this release has fought
> hardest: a canary that hashed nothing on both sides and compared equal; a transcript gate that
> returned 0 on an untracked file; an aggregate exit that never reached its own steps.

So the shape is: **run every suite, record each outcome, print a summary naming every failure, exit
non-zero if the failure count is greater than zero.**

Corollaries that follow from the invariant, not from taste:

- **A crash is a failure, not an absence.** A suite that dies on a signal or times out must be
  recorded as failed, never skipped — otherwise the change converts a hard failure into a silent gap.
- **The summary is the deliverable.** A run that exits non-zero without naming *which* suites failed
  is no more useful than the current abort.
- **Ordering must stay deterministic**, so two runs of the same tree produce the same report.

## 3. What this slice does NOT do

**It does not fix the fractional-id tooling defects.** Those are a separate cross-cutting unit,
**SLICE-ID-HARDENING** (`seq-204` ruling 1) — see §5.

**It does not fix the 23 hidden suites.** Their state is unknown, and their yield could be zero
failures or fifteen. That unbounded scope is precisely why the HITL split this from Slice 40
(`seq-202`): Slice 39.5 **reports** the true red list; the disposition of what it finds is a separate
decision.

The two already-owned red suites stay owned by Slice 40 — `test_actionlint_fixture`
(TC-16/F-30) and `test_check_governed_surface_pin` (its provenance arm hardcodes a stale commit;
handed over by Slice 39). ⚠ Slice 39.5 **may** convert `test_actionlint_fixture`'s internal
fail-fast loop, because that conversion is what *reveals* its second defect — but it does not fix
either defect.

**It publishes nothing, bumps no version, and touches no manifest.**

## 4. Scope

**In:** `scripts/agent-test.sh`'s fail-fast structure; the per-suite loop in any script Slice 39.5
touches that stops at its first failure; the true red-suite report; **and the CI baseline** (below).

### The CI baseline — folded in at `seq-204` ruling 2

The publish gate now requires **every `ci.yml` job to conclude `success`** (`seq-202`). **Nobody knows
what that looks like.** The last green on `main` (`788b74c1`) ran **four jobs on the docs-only path** —
`commission-manifest`, `verify` and `security` never executed — so it is a *vacuous* green, the same
class this unit exists to eliminate locally.

So the same discovery runs one level up: **force a full CI pass and report the TRUE red list there
too.** Note `test_commission_manifest.sh` was locally rc=1 until the de-laddering, and a prior full run
showed `verify`/`security` red on pre-existing pyright errors (`dense_disabled`, `IdSpace`, `reason`)
unrelated to any of this. **Report them; do not fix them** — disposition is a separate decision, for the
same reason the 23 hidden suites are not fixed here.

**Out:** fixing the hidden suites; anything in `.github/` (Slice 40's exclusive territory this
release); version fields; the governed surface; schema; eu7 (zero runs, F-28).

⚠ **`run_capped` is the seam.** Whatever mechanism records outcomes must keep `run_capped`'s existing
output-capping behaviour — the caps exist because unbounded suite output has overflowed budgets before
(`test_steward_orient` enforces a 4096-byte payload cap for exactly this reason).

## 5. The fractional-id tooling defects — a SEPARATE unit

`seq-204` ruling 1 put the whole fix in its own cross-cutting unit, **SLICE-ID-HARDENING**, which also
carries no slice number and no `R-20-xx` id. It is **not this unit's work**, and is summarised here only
so the two are not confused.

Six silent-wrong sites, each measured, each exiting 0: `check-board-currency.sh:123` capturing `39` from
`"Slice 39.5"` so a real landing merge is skipped as *superseded* — in **both** `preflight --landing`
and the always-on CI job; `commission-manifest.sh:701` filtering a float out of the predecessor set, so
a brief prints a base SHA that silently drops a whole unit's work; `commission-manifest.sh:497`
compiling an **identical** filename pattern for 39 and 39.5, which can defeat the TC-37 vacuous-pass
guard using a neighbour's memo; `preflight.sh:131` accepting one unit's CLOSED witness as another's, in
the gate whose stated purpose is catching a dependency that is not actually closed.

⚠ **The recurrence arms are that unit's real deliverable.** Nothing in the repo would catch the next
occurrence — and `test_commission_manifest.sh:1718` replicates the generator's own filter verbatim, so
it would *confirm* the defect rather than catch it.

## 6. Acceptance

**No AC is minted and no new `R-20-xx` id beyond `R-20-HARNESS`** — gate by test name.

1. `scripts/agent-test.sh` runs **all 31** registered suites regardless of individual failures.
2. It **exits non-zero** when any suite failed, and **zero** only when all passed — proven by a
   **control in both directions**: force one suite to fail and show a non-zero exit *with that suite
   named*; and show a clean tree exits 0.
3. The summary **names every failing suite**, not just the first.
4. A suite that crashes or times out is reported as **failed**, never skipped.
5. **The true red-suite list is delivered as the slice's finding** — every one of the 31 with its real
   exit code, including the 23 that have never run.
6. Full-workspace `cargo clippy --workspace --all-targets` **and** `cargo check --workspace
   --all-targets` both exit 0.
7. **The TRUE CI red list is delivered** from a forced full `ci.yml` run — every job with its real
   conclusion. ⚠ A run that took the `docs_only` short path **does not count**; say how many jobs
   actually executed, so the baseline cannot itself be vacuous.
