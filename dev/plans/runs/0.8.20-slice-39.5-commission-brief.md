## 1. What this unit does

Convert `scripts/agent-test.sh` from **fail-fast** to **collect-all-then-report**, and deliver the **TRUE
red list — locally AND in CI**.

### ⛔ The invariant (design doc §2)

> **A run that had any failure MUST still exit non-zero.**

Continue-on-failure changes *when* the harness stops — never *whether* a failure counts. Corollaries, which
follow from the invariant and not from taste:

- **A crash or timeout is a FAILURE, never a skip.**
- **The summary is the deliverable.** A non-zero exit that does not name *which* suites failed is no more
  useful than today's abort.
- **Ordering stays deterministic.**

### ⛔ `run_capped` IS SHARED — its return contract must NOT change

`scripts/lib/agent-output.sh` is sourced by **five** scripts, all `set -euo pipefail` fail-fast **[V]**:
`agent-test.sh`, **`agent-lint.sh` (5 uses)**, **`agent-typecheck.sh` (3)**, **`agent-build.sh` (3)**,
**`agent-lint-md.sh` (9)**. It is also **copied verbatim into a fixture repo** by
`scripts/tests/test_lint_md_hard_fail_on_missing_linter.sh:39`. And `agent-verify.sh` chains
lint → typecheck → security → test, short-circuiting on each.

> **If you make `run_capped` itself record-and-return-0 — the obvious reading of "`run_capped` is the seam" —
> then `agent-lint`, `agent-typecheck`, `agent-build` and `agent-lint-md` ALL silently become
> continue-on-failure with a zero exit.** That manufactures the exact vacuous green this unit exists to end,
> in four scripts nobody is looking at, plus a fixture that copies the file verbatim.
>
> **`run_capped`'s return contract is UNCHANGED for its four other callers. The collect-all wrapper lives in
> `agent-test.sh`.**

⚠ Whatever you build must still **preserve `run_capped`'s output capping** — the caps exist because
unbounded suite output has overflowed budgets before (`test_steward_orient` enforces a 4096-byte cap for
exactly that reason).
