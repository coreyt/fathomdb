# Slice 23 pickup review — 2026-08-08

## Verdict: READY

The approved design and plan were re-read before implementation. No P1/P2
change is required; Slice 23 moves from proposed to ready on this branch.

## Re-verified premises

- `search_text_only_view_with_limit` dispatches direct text-only search through
  `ReaderRequest::Search` with no query vector.
- The reader derives the current node FTS SQL limit from `query_vector.is_none()`;
  edge FTS remains separately collected without that SQL limit; text candidates
  are RRF-fused and final truncation occurs afterward.
- `slice18_retrieval_result_limits.rs` proves cardinality and limit validation,
  not direct-text ordered prefix stability.
- Existing SDK test homes are
  `src/python/tests/test_slice18_retrieval_result_limits.py` and
  `src/ts/tests/slice18-retrieval-result-limits.test.ts`; existing validity
  fixtures demonstrate explicit `ReadView.valid_as_of` / `validAsOf` use.

## Implementation constraints retained

The RED fixture must exercise an edge body duplicating a node outside the
first-ten node window. The Rust/Python/TypeScript tests must use real databases
and the `ReadView` comparison must freeze its validity time explicitly. The
private direct-text discriminator is required so ordinary hybrid no-vector
fallback behavior is unchanged. Publication remains held.
