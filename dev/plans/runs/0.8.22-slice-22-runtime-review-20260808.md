## Verdict: CONCERN

Two P2 findings require `FIX-1` and focused re-review. Slice 22 cannot close
until both are resolved.

### 1. [P2] Purity test does not prove no scheduler wake

`slice22_projection_status.rs` snapshots durable projection tables but not
in-memory scheduler state. A mistaken `notify_new_work()` can set the
scheduler's pending-scan state without changing the no-runtime fixture's
durable snapshot. `FIX-1` must add a narrowly scoped scheduler state/work
snapshot or test seam, and prove it is unchanged around repeated status reads.

### 2. [P2] Documentation overstates the reader-worker concurrency path

The implementation deliberately uses an ordinary Engine connection lock. It is
pure, but it is not a ReaderWorkerPool read. `FIX-1` must correct the generic
claims in Python/TypeScript SDK source docs and public API references: separate
the reader-worker verbs from `projection_status`, state that the latter may take
the connection lock, and retain that no separately opened read-only SQLite mode
is promised.
