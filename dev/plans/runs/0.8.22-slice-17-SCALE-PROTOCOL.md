# 0.8.22 Slice 17 — SCALE-PROTOCOL

## Outcome

Slice 17 pre-registers the 0.8.23 scale-characterization protocol in
dev/design/0.8.23-scale-characterization-protocol.md. This record is protocol
evidence only. It contains no benchmark execution, corpus/model download,
latency measurement, throughput measurement, supported-scale claim, or release
approval.

## Deferred execution boundary

The protocol may be executed only after the complete 0.8.22 dependency stack
is the candidate under test, including the coupled rusqlite and sqlite-vec
migration. The 0.8.23 executor must create the versioned result artifact and
apply its prerequisite, sample-sufficiency, and environmental-validity rules.
No absent, partial, or invalid result can be reported as a passing scale
outcome.

The protocol characterizes the shipped non-ANN two-phase vec0 vector path:
binary bit-KNN generates a candidate set and f32 reranking operates only within
that set. It does not imply exhaustive f32 search over the full fixture, and it
does not authorize ANN, HNSW, IVF, or other index implementation, or change
existing performance gates or a supported-scale limit.

## Protocol contents

The design document fixes:

- the production Engine::search path and deterministic AC-013 fixture,
  generator/query seeds, 384-d dimension, and 10k/100k/1M points;
- candidate, lockfile, schema, toolchain, host CPU/GPU, capacity, and
  load-isolation provenance;
- labelled process-cold and warm treatments, five independent repetitions, and
  non-pooled percentile summaries; `process_cold` requires five first-query
  observations (one per completed repetition), while `warm` requires five
  completed repetitions with 1,000 warm-query observations each;
- result states for deferred, missing, insufficient, invalid, and valid data;
- the rule that a valid characterization is fixture-scoped evidence, never a
  passing threshold or firm supported-scale statement.
