# Slice 17 — SCALE-PROTOCOL

## Mandate

Pre-register the protocol that 0.8.23 will use to characterize FathomDB's
supported scale. This slice creates a protocol and result-artifact contract;
it does not run a benchmark, make a performance claim, or change a supported
scale limit.

## Required reading

- `dev/plans/plan-0.8.22.md`
- `dev/plans/0.8.6-0.8.16-PROGRAM-SEQUENCING.md` §4 (0.8.22–0.8.24)
- `dev/design/perf-gates.md`
- `dev/design/ann-index-vec0.md`
- `dev/design/1-2M-chunk-scaling-vector-latency-roadmap.md`
- `scripts/perf-experiments/README.md`
- `scripts/perf-experiments/collect-host-spec.sh`
- the committed Slice 12 run record

## Deliverables

1. Add one design/protocol document under `dev/design/` that names the exact
   production path under test, corpus/fixture identity and pinning, candidate
   revision/schema/dependency-lock capture, host and CPU/GPU capture, cold and
   warm treatment, repetitions, metrics/percentiles, and artifact schema.
2. Define how the protocol reports a missing prerequisite, insufficient
   samples, environmental invalidity, and a valid characterization. It must
   never turn missing or invalid data into a passing scale result.
3. Reuse existing performance-runner and host-spec conventions where they fit;
   do not create a parallel benchmark framework or a second authority index.
4. Add a plan-facing run record under `dev/plans/runs/` that lists the protocol
   and states that execution is deferred until after the complete 0.8.22
   dependency stack. It must contain no fabricated measurements.

## Boundaries

- No benchmark or real-corpus scale run. Do not download a corpus or model.
- No source, test, workflow, public API, performance threshold, or release
  state change.
- Do not claim that existing 10k/100k/1M perf gates establish the future
  supported-scale envelope.
- Keep ANN/HNSW out of the protocol's implementation scope; it remains a 2.x
  decision. This protocol characterizes the shipped exact-search stack.
