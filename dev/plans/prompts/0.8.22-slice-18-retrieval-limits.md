# 0.8.22 Slice 18 — Ranked Retrieval Limits

## Mandate

Implement the accepted contract in `dev/design/retrieval-result-limits.md`.
This is a public Rust/Python/TypeScript retrieval change. Work in a fresh
worktree cut from current `origin/main`; do not alter release-state or plan
files. Follow TDD: commit or stage the failing tests before implementation.

## Required behavior

- Direct hybrid, text-only, and projected-text retrieval default to 10 results.
- Callers can request `K` in `1..=100`; zero, negative binding input, and values
  above 100 fail with the established typed invalid-argument error.
- Hybrid vector rerank fanout reaches the requested K; a request for 20 or 50
  must not silently stop at the legacy internal value of 10.
- Hybrid, text-only, and projected-text result limits apply after validity and
  metadata filtering and after applicable ranking/fusion/reranking.
- `search_expand` accepts `search_limit` for its initial ranked `search_hits`.
  Its graph-neighbor cap remains 50 per root; do not add an expansion knob.
- Keep `set_search_limit_for_test` test-only. Do not expose it through either
  SDK or make an environment variable part of the production hot path.

## API shape

- Python: keyword-only `limit=10` on the three direct methods and
  `search_limit=10` on `graph.search_expand`.
- TypeScript: optional `limit` / `searchLimit` fields in the public options
  shape; preserve existing positional compatibility only where the wrapper
  already provides it.
- Rust: retain each default-ten convenience form and add an explicit-limit form
  for each ranked family. Document the exact final symbols in
  `dev/interfaces/rust.md` as part of the implementation.

## Required tests

Write red tests first. At minimum, cover default 10, `K = 5`, `20`, `50`, and
`100`; typed rejection for zero/negative/101; hybrid vector depth at 20/50;
post-filter result filling for both body and property FTS; and
`search_expand.search_hits` capped independently of its 50-per-root expansion.
Cover engine behavior and both bindings. Update stubs/type declarations and
public interface documents in the same change.

## Verification and handoff

Run the relevant targeted Rust, Python, and TypeScript tests, then
`./scripts/agent-verify.sh`. Commit only source/tests/interface documentation
inside the slice worktree. Write the required structured output artifact with
the baseline SHA, commit SHA, changed paths, tests and exit codes, and known
limitations. The orchestrator will arrange independent review before landing.
