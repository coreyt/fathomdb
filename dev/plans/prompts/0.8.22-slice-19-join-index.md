# Slice 19 — JOIN-INDEX

> **Execution status:** complete locally; protected-branch landing remains
> pending.

## Mandate

Remove the repeated canonical-table scan from current FTS hydration by adding
unconditional `write_cursor` lookup indexes to `canonical_nodes` and
`canonical_edges`. This is a schema-and-engine performance repair; it changes
no public SDK signature or retrieval ranking contract.

`canonical_nodes_state_active_idx` already indexes `write_cursor` for active
rows only. It is not the required general join index: current node queries
retain legacy/orphan rows and use predicates for which the partial index is
not a sufficient contract. The new indexes must therefore be distinct,
unconditional, and non-unique.

## Required behavior

1. Advance `SCHEMA_VERSION` from 25 to 26 with one additive, index-only
   migration:

   ```sql
   CREATE INDEX IF NOT EXISTS canonical_nodes_write_cursor_idx
       ON canonical_nodes(write_cursor);
   CREATE INDEX IF NOT EXISTS canonical_edges_write_cursor_idx
       ON canonical_edges(write_cursor);
   ```

2. A fresh database and a database upgraded from schema 25 both contain both
   indexes. The migration remains forward-only, transactional, and idempotent.
3. The node-body FTS plan uses the new unconditional node cursor index, and
   the edge-body FTS plan uses the new edge cursor index. Projected-text FTS
   retains the applicable existing active-node partial index
   (`canonical_nodes_state_active_idx`). Tests must pin that appropriate index,
   rather than a brittle whole-plan string or elapsed-time threshold.
4. Record a reproducible ingest and migration-cost measurement: corpus/fixture
   identity, row count, SQLite build, warm/cold treatment, command, and raw
   timings. This is evidence, not a CI latency gate.

## Explicit boundary

Do **not** add an SQL `LIMIT` to edge FTS in this slice. Edge filtering occurs
after SQL retrieval and hybrid fusion can make a deeper edge candidate visible;
a branch-local SQL limit is not generally semantics-preserving. A later slice
may pursue a post-filter accepted-hit bound or another proven-safe design.

Hybrid's deliberate unbounded pre-fusion text ranking is also out of scope.
