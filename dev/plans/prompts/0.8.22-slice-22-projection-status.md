# Slice 22 — PROJ-STATUS

> **Execution status:** complete locally; protected-branch landing remains
> pending.

## Mandate

Add a governed, pure-read projection-status API so a caller can observe current
runtime availability, per-projection dense readiness, and unsupported vector
kinds without re-applying a caller-owned declaration. This is a new public verb
in Rust, Python, and TypeScript; it requires a fresh governed-surface decision
and conformance update before implementation.

## API contract

The proposed spellings are:

- Rust: `Engine::read_projection_status()`;
- Python: `fathomdb.read.projection_status(engine)`; and
- TypeScript: `read.projectionStatus(engine)`.

It returns one explicitly new facade status type, distinct from the existing
internal lifecycle `ProjectionStatus` enum. The public names are
`ProjectionRuntimeStatus`, `ProjectionRuntimeStatusEntry`,
`ProjectionRuntimeUnavailabilityReason`, and `ProjectionStatusDenseReadiness`:

- Rust exports the named structs/enums with PascalCase variants;
- Python exports frozen dataclasses for the two records and `Literal` aliases
  for the two closed string vocabularies; and
- TypeScript exports the two interfaces and the equivalent string unions.

The bindings map the Rust enums to the exact lower-case strings below. The
facade types are not a renamed `ProjectionSpec`, `ProjectionDelta`, or the
internal lifecycle enum.

`ProjectionRuntimeStatus` contains:

- `runtime_embedder_available: bool`, which means that this session has an
  embedder accepted by the existing identity and vector-equivalence safeguards;
- `runtime_unavailability_reason: "none" | "no_runtime" |
  "vector_equivalence_disabled"`, a lowercase wire contract that is `"none"`
  exactly when the runtime is available and otherwise tells the caller why this
  session cannot retrieve densely;
- one entry per declared projection, each with
  `not_declared | unavailable | embedding | ready` (`not_declared` applies when
  that declaration has no *effective vector arm*); and
- the current sorted `vector_unsupported_kinds` report, which is `[]` when no
  projection declares a vector arm.

An effective vector arm means the stored declaration currently has both a
searchable role and a vector arm (`StoredProjection::wants_vector`), not merely
a legacy vector sub-object. A legacy, non-searchable vector sub-object is
therefore `not_declared` for this status API and does not cause unsupported
kinds to be reported.

The status call is pure: through an ordinarily opened `Engine`, it must not
configure projections, schedule or wake work, or write storage. It does not
promise support for a separately opened read-only SQLite handle. Its readiness
remains corpus-wide under the current shared dense pipeline; per-projection
entries therefore repeat the same runtime state for every declared effective
vector projection.

Before RED tests, record the new C5 governed-read verb in the allowlist/signing

## Required review

Independent review must verify that the new method is a status read rather
than a configuration echo, that runtime availability and its reason have no
overloaded meaning, and that it does not claim per-attribute readiness the
engine cannot currently observe.
