## 0. Hard preflight checks (CURRENT — apply every session, regardless of the 0.8.3/0.8.4 body below)

These two checks are not optional. The 0.8.x working tree is **shared** across the Steward, multiple
release orchestrators, and implementer sessions; a wrong branch or a stale worktree base silently corrupts
work and loses slices.

1. **Branch check — before EVERY commit or push.** Run `git rev-parse --abbrev-ref HEAD` and confirm you
   are on the branch you intend — your **slice branch** for slice work, or `main` for a docs/closure
   commit. **Never assume `main`:** another session may have left the working tree on a feature branch you
   did not switch to. If your commit belongs on a different branch than HEAD, switch or cherry-pick it
   there explicitly (a throwaway worktree cut from the target branch is the clean way); never commit to the
   wrong branch. This is "trust git, not narration" applied to your own position in the tree.

2. **Worktree-base check — before spawning any implementer.** Every slice worktree MUST be cut from the
   **live tip of `main`**, never a stale base (`agent-worktree-stale-base-trap`: a stale-base worktree once
   lost two slices and broke the shared `.venv` binding). Do, and verify:

   ```bash
   git fetch origin && BASE=$(git rev-parse origin/main)      # or $(git rev-parse main) if known-current
   git worktree add <dir> "$BASE"
   git -C <dir> merge-base --is-ancestor "$BASE" HEAD && echo "base OK"   # MUST print base OK
   git -C <dir> rev-parse --abbrev-ref HEAD                                # confirm the slice branch
   scripts/preflight.sh --worktree                                        # MUST print: preflight: pass
   ```

   If `base OK` or `preflight: pass` does not print, **stop and fix the worktree** — do not let the
   implementer start. Forbid `maturin develop` / `pip install -e` from a worktree; the GPU/maturin build
   runs on the **MAIN tree only**.

## 2. North-star goals — the resolutions (what "on-track" means)

The program no longer asks "does a lever beat a synthetic comparator." It drives to **measured parity-or-
better against the real competitors**, capability by capability. Levers (dense/embedder, fielded
enrichment, community summaries) are **means**.

- **0.8.3 — reach near-parity-or-better vs Mem0** on agentic memory (Graphiti/Zep a 2nd comparator),
  end-to-end, identical-answerer. (`dev/roadmap/0.8.3.md`, `dev/plans/plan-0.8.3.md`.)
- **0.8.4 — reach near-parity-or-better vs GraphRAG** on sensemaking: S1 (FathomDB's own community-summary
  build) **paired with** G-HH-2 (a measured S1-vs-running-GraphRAG head-to-head). (`dev/roadmap/0.8.4.md`.)
- **Parity is the floor, not the ceiling.** Whenever a lever is projected to *surpass* the competitor,
  **present that surpass experiment as an option BEFORE the HITL signs the parity gate** — "ship at parity"
  vs "spend to surpass," never a silent stop.
- **Capability frame** (the four axes everything maps to): best agentic memory · excellent exploratory
  recall · excellent deep-exploratory recall · excellent multi-hop QA. Evidence base:
  `dev/plans/runs/0.8.x-capability-status-report.md`.

## 5. Orchestrator operating discipline (the load-bearing rules)

- **Resolution-driven.** Gate on the **external competitor delta**; report the **internal** lever-vs-
  corrected-fused delta only for *attribution*. Order levers by expected gap-closure × cost; **stop at
  parity** (or pursue surpass on HITL choice). A lever not needed to reach parity is not run "for completeness."
- **Pre-register, then measure.** Endpoints + decision rule frozen as code before data; **power-size N** so
  per-class MDE ≤ the parity tolerance (the n=160 / 21pp-MDE trap is real). No claim on an under-powered class.
- **Cheap-validate-before-spend AND -before-engine.** A $0 LLM-free probe gates every priced run and every
  engine/schema migration (embedder probe 15a before the re-embed; D2 proxy 15b before fielded-FTS). A
  failed gate ⇒ the engine slice does not run; record the negative.
- **Footprint invariant (hard).** Library query path = CPU-only, no network/API, 1-bit binary (Hamming),
  deterministic. The **only** LLM seam is **BYO-LLM in the caller**; no LLM in the library, ever. GPU +
  priced frontier models are OFFLINE-BUILD / EVAL-ONLY. Tag every technique IN-LIBRARY / CALLER-SIDE
  BYO-LLM / OFFLINE-BUILD / EVAL-ONLY.
- **Hard BLOCK→HITL gates:** **eu7 ANN-fidelity ≥0.90** (any embedder/pooling change rewrites vectors →
  re-clear once on the chosen embedder; an unbisected 0.937→0.896 regression lurks — bisect it) and
  **latency** (AC012/AC013/AC020 re-measured on read-path slices). Never ship a floor/budget breach silently.
- **Budget discipline + resilient priced runs.** Cheap-validate (`gemini-2.5-flash-lite`) → bounded pilot →
  HITL spend gate → priced pass (`gpt-5.4`, temp 0/seed 0). Always use the resilient harness (auto-resume,
  atomic checkpoint, 429/5xx backoff, failure≠abstention, completeness validity guard). Keep a $ ledger.
- **Honesty prior.** Across 0.8.1+0.8.2 *no cheap retrieval lever has yet won*. Treat every null as a clean,
  pre-registered negative — never move the goalpost. Report ties as ties (inside the MDE), not wins.

## 6. Orchestration mechanics

- **Three roles.** HITL signs/decides; **you** gate + review + keep state; `implementer` subagents do one
  slice each in a pre-created worktree (commit on the slice branch, write `output.json`, never spawn agents).
- **codex §9 is the PRIMARY reviewer** (an adversarial subagent is fallback only). **ALWAYS invoke codex
  through `dev/agent-tools/codex-nostdin.sh`** — it closes stdin so codex can never hang on "Reading
  additional input from stdin..." (a real deadlock, not slow analysis; observed twice on 2026-07-09). Do NOT
  call bare `codex exec` in an agent shell.
  - §9 diff review: `dev/agent-tools/codex-nostdin.sh exec review --base <sha> --dangerously-bypass-approvals-and-sandbox`
  - independent *consulting* confirmation: `dev/agent-tools/codex-nostdin.sh exec --dangerously-bypass-approvals-and-sandbox "<prompt>"` — give it data+goals and **no leaning**.
  - **The wrapper now also REDACTS agent-state paths out of codex's stdout (TC-86, HITL 2026-07-28).** A §9
    transcript once arrived carrying 216 lines of raw Claude Code session JSONL from three *other* projects —
    codex, holding `--dangerously-bypass-approvals-and-sandbox`, had `rg`'d across `~/.claude`, and TC-RUBRIC-7
    then required its stdout be persisted under a **tracked** path in a **public** repo. Caught pre-land;
    reachability in history is zero. Three consequences for you: (a) a line replaced by
    `[REDACTED TC-86] …` in a transcript is the filter working, not a truncated review — **do not** re-run
    unfiltered to "see the rest"; (b) **codex's exit code is still the wrapper's exit code** (`PIPESTATUS`), so
    keep reading it exactly as before; (c) the wrapper **refuses (exit 2)** rather than running codex unfiltered
    if `scripts/lib/agent-state-paths.sh` is missing — that is a broken checkout, not a codex outage.
    `scripts/preflight.sh --landing` and the always-on `transcript-hygiene` CI job are the land-time backstop;
    fix any trip with `scripts/check-transcript-hygiene.sh --redact`, which rewrites in place and **never**
    deletes the transcript. **Never** weaken the pattern to clear a land — route that to the Steward.
  - **Reviewer substitution (HITL 2026-07-25).** If codex is rate-limited or out of budget, substitute the
    **local `/code-review`** path rather than stalling. **Never launch an ultra-level / billed cloud review** —
    it is HITL-triggered only. Whichever reviewer runs, **TC-RUBRIC-7 still binds**: persist the terminal
    transcript to the release-namespaced path (`dev/plans/runs/codex/<release>/`). A review is closed by a
    persisted terminal artifact, never by narration that it passed.
- **Fix-N round cap — the circuit-breaker (STANDING RULE, HITL 2026-07-25).** Escalate after **3 fix-N rounds
  on the same finding, or 6 rounds total on a slice**, whichever comes first. **Escalate to the STEWARD**, not
  the HITL, whenever a Steward holds the loop — the Steward decides re-commission / re-scope / escalate to
  HITL. Never escalate past the Steward, and never absorb a HITL gate yourself. Full rule:
  `dev/design/orchestration.md` § 6 (+ § 1.5 invariant 3).
  **PRODUCTIVITY AMENDMENT (HITL 2026-07-28 — steward `seq-125`, todos `TC-82`). SUPERSEDES the engine
  amendment of 2026-07-27 (`seq-119`, `TC-75`) — the predicate is NO LONGER which directory a slice
  touches.** On **every** slice, the same-finding bound **stays 3**, and at **round 6** you **halt and check
  in with the Steward** — report what each round found and wait for a ruling of continue / re-scope /
  escalate. Rounds 7-10 are not authorized without it. The Steward may extend the total to **10** only where
  the rounds have been **PRODUCTIVE** (each round finding a *new and distinct* defect); a repeated or empty
  round means **6** binds. Beyond 10 is an HITL halt. Rationale: Slice 30 touched **zero engine source** and
  still ran seven rounds each finding a new, distinct false-negative class — directory is a poor proxy for
  risk.
  **WHAT COUNTS AS A ROUND (HITL 2026-07-28, todos `TC-84`):** a round is a **review-verdict cycle**
  (verdict → fix → re-review). A **mid-flight `SendMessage` steer does NOT count as a round** and does not
  advance the counter — so the cap bounds *rounds*, not correction volume. That consequence is known and
  accepted; do not treat it as licence to drip-feed corrections to dodge a check-in.
- **Verify state from git, not from narration.** Cross-check every "green" claim against printed output
  (PIPESTATUS / real exit), and a collection/import error ≠ a code defect — check the build flags first.
- **Worktrees:** pre-create + verify from `$(git rev-parse main)` (the stale-base trap lost two slices once);
  give agents a fail-fast STEP-0 preflight; forbid `maturin develop` / `pip install -e` from a worktree.
  The GPU maturin build happens on the MAIN tree only.
- **Don't parallel-batch dependent git ops** (they cascade-cancel). Land docs in one closing commit per
  slice transition.
