# Slice 21 — PROJ-STATE

## Mandate

Make `vector_dense_readiness` truthful when a `searchable→vector` declaration
exists but the engine has no runtime embedder, and automatically graft the
declared vector backfill on a later safe embedder open. Update the vocabulary
documentation at the same time.

This is a public behavior change across Rust, Python, and TypeScript. It adds
no method, storage field, or schema migration, but it changes a returned enum
value and causes a qualifying open to repair durable scheduler state.

## Gate: F5 decision and C1 conformance record

Before RED tests or implementation, record the governing decision and update
the byte-pinned OPP-12 C1 contract. The decision is:

> `DenseReadiness` is `{unavailable, embedding, ready}`. For a declared vector
> projection, `unavailable` means no usable dense runtime (absent or
> equivalence-refused); `embedding` means usable runtime with eligible
> outstanding work; `ready` means usable runtime with that work quiescent.
> `pending` remains admission-only. Readiness is engine-set, accept-inert
> metadata. `drain` remains a passive barrier: successful drain implies `ready`
> only with a usable dense runtime. Boot graft is permitted only after identity
> and equivalence acceptance, commits enrolment/requeue atomically before
> notification, and never reopens `failed` terminals.

The record changes all of the following in one reviewed, intentional commit:

1. append the HITL ruling through `ledgerwrite` to
   `dev/steward/steward-ledger.jsonl`;
2. amend `dev/design/record-lifecycle-protocol/OPP-12-C1-converged-contract.md`;
3. fully re-derive, rather than hash-only edit,
   `scripts/c1-conformance-pin.json`, its checker, and its checker tests;
4. record the governed-surface decision/signature commentary in
   `src/conformance/governed-surface-allowlist.json`; and
5. update all three interface contracts and public binding type/doc surfaces.

The two existing vacuous-readiness pins are deliberately superseded and
rewritten, not deleted. A cross-repository notice is tracked separately and
does not block a safe FathomDB landing after the local decision is recorded.

The implementer halts if this complete record is absent or if the signed
spelling is not `unavailable`.

## Required behavior

- For a declared vector projection, `read.projections` reports:
  - `unavailable` when the runtime is absent or not safety-approved for dense
    work;
  - `embedding` when a live, safety-approved runtime has outstanding projection
    work; and
  - `ready` only when that runtime is live and the shared work predicate is
    quiescent.
- A non-vector projection continues to expose no dense readiness (`None`).
- Define one `usable_dense_runtime` predicate: an embedder exists and its
  vector-equivalence check has not refused dense work. Use it in
  `read_projections`, boot graft, `configure_projections`, late enrolment,
  scheduler construction/dispatch, and the final open notification.
- Before an otherwise-unregistered durable vector declaration can graft, run an
  identity/equivalence preflight that covers that prospective vector arm. A
  refusal leaves enrolment, terminal rows, vector rows, and notifications
  unchanged.
- On open with a usable dense runtime and a durable vector declaration, the
  engine atomically enrols committable kinds and re-enqueues only stranded
  `up_to_date` rows lacking vector rows. Commit precedes runtime notification.
- The boot graft never reopens a `failed` terminal and is idempotent against
  ordinary scheduler ownership. With no usable runtime it performs no *new*
  boot-graft/enrolment work; it does not erase already-enrolled durable work.
- For a declared vector projection, successful `drain()` implies `ready` only
  when a usable dense runtime is live and eligible shared work is quiescent. A
  fresh no-runtime declaration may drain successfully with no work and remain
  `unavailable`; an already-enrolled no-runtime session may instead time out
  while durable work remains, but still reads `unavailable`.

## Required review

Independent review must examine the usable-runtime predicate at every scheduler
entry point, prospective-arm preflight ordering, transaction boundaries, crash
retry behavior, C1 pin derivation, and public compatibility. It must reject a
design that merely changes a label while leaving a `ready`-without-vector or a
refused-runtime-mutation path reachable.
