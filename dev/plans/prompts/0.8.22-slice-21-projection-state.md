# Slice 21 — PROJ-STATE

## Mandate

Make `vector_dense_readiness` truthful when a `searchable→vector` declaration
exists but the engine has no runtime embedder, and automatically graft the
declared vector backfill on a later safe embedder open. Update the vocabulary
documentation at the same time.

This is a public behavior change across Rust, Python, and TypeScript. It adds
no method, storage field, or schema migration, but it changes a returned enum
value and causes a qualifying open to repair durable scheduler state.

## Gate: F5 decision record

Before RED tests or implementation, record the governing decision in the
release/state and interface records:

1. `unavailable` is the third `DenseReadiness` spelling; `ready` is never
   observable for a declared vector projection without a live runtime embedder.
2. The two existing vacuous-readiness pins are deliberately superseded and
   rewritten, not deleted.
3. The OPP-12 readiness enumeration is amended through its governed process.
   Any cross-repository notice is tracked separately and never blocks a safe
   FathomDB code landing after the local decision is signed.

The implementer halts if this record is absent or if the signed spelling is not
`unavailable`.

## Required behavior

- For a declared vector projection, `read.projections` reports:
  - `unavailable` when the runtime is absent or not safety-approved for dense
    work;
  - `embedding` when a live, safety-approved runtime has outstanding projection
    work; and
  - `ready` only when that runtime is live and the shared work predicate is
    quiescent.
- A non-vector projection continues to expose no dense readiness (`None`).
- On open with a live, safety-approved runtime and a durable vector declaration,
  the engine atomically enrols committable kinds and re-enqueues only stranded
  `up_to_date` rows lacking vector rows. Commit precedes runtime notification.
- The boot graft never reopens a `failed` terminal, never runs without a
  runtime embedder, and is idempotent against ordinary scheduler ownership.
- The graft must not enqueue work before the runtime's existing identity and
  vector-equivalence safety checks have accepted that runtime.
- For a declared vector projection, successful `drain()` implies `ready` only
  when a safety-approved dense runtime is live and eligible shared work is
  quiescent. A no-runtime `drain()` may succeed with no work but leaves the
  readiness `unavailable`.

## Acceptance criteria

| ID | Requirement | Falsifiable acceptance signal |
| --- | --- | --- |
| S21-AC1 | No-runtime readiness is honest. | A declared vector projection reads `unavailable`, never `ready` or `embedding`. |
| S21-AC2 | A later safe runtime open heals the stranded declaration. | Fixture observes `embedding`, `drain`, `ready`, and vector rows at rest. |
| S21-AC3 | Repair preserves failure and scheduler invariants. | Tests prove no failed-terminal reopen, no work with no runtime, and exactly one embed per repaired row. |
| S21-AC4 | `drain()` readiness is honest in both runtime modes. | Rust, Python, and TypeScript tests prove a no-runtime no-op `drain()` retains `unavailable`, while a safe live runtime reaches `ready` after work is quiescent. |
| S21-AC5 | All SDKs express the same vocabulary. | Rust, Python, and TypeScript tests and public type declarations accept/output the same three literals. |
| S21-AC6 | Existing vocabulary traps are corrected. | Interface and API docs explain `None`, non-disjoint `built`/`deferred`, qualified `drain() → ready`, and the new unavailable state. |
| S21-AC7 | The full workspace remains healthy. | Full-workspace clippy/check with `--all-targets` and `./scripts/agent-verify.sh` exit 0. |

## Required review

Independent review must examine open ordering, transaction boundaries, crash
retry behavior, vector-equivalence gating, and public compatibility. It must
reject a design that merely changes a label while leaving a `ready`-without-
vector path reachable.
