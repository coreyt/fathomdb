# 0.8.22 candidate dry-run

Run this only after the candidate commit is on `origin/main`. It dispatches the
release workflow without creating or pushing a `v*` tag, so every publish step
stays dry-run-only.

```bash
candidate="$(git rev-parse --verify <candidate-commit>^{commit})"
git merge-base --is-ancestor "$candidate" origin/main
gh workflow run release.yml --ref main \
  -f dry_run=true \
  -f release_version=0.8.22 \
  -f candidate_commit="$candidate" \
  -f recovery_skip_npm=false
```

The workflow rejects a missing, abbreviated, unresolved, or mismatched
candidate SHA. `verify-release` proves that its checkout equals the supplied
SHA, retains Axis-W/version/CHANGELOG checks, and verifies the candidate is
reachable from `origin/main`. All release jobs use that same checkout ref.

Do not run a non-dry dispatch or push `v0.8.22` for this rehearsal: either can
enter the real publishing path.
