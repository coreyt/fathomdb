# scripts/shellcheck-sc2312-ratchet.txt — files NOT YET covered by SC2312
# (check-extra-masked-returns), the check for this repo's own historical bug
# class (a command whose non-zero exit is swallowed by a command substitution
# or by SIGPIPE upstream of a pipe under `set -o pipefail`).
#
# 0.8.21 Slice 30 (SHELLCHECK), design of record
# dev/design/ci-verify-robustness-review.md R1.1, which authorises exactly this
# shape: "If the finding volume is unmanageable, ratchet ... rather than by
# suppressing the check. A per-directory ratchet is honest: it says 'not yet
# covered'. A global disable says 'covered' while covering nothing."
# This is the per-FILE form of that ratchet — strictly tighter than per-directory.
#
# RULES, enforced by scripts/agent-lint-shell.sh:
#   * Every tracked *.sh NOT listed here has SC2312 enforced. New files are
#     therefore covered by default; nothing has to be remembered.
#   * The list may only SHRINK. A listed file that has become SC2312-clean makes
#     the gate FAIL until its line is deleted, so an exemption cannot rot into a
#     permanent hole.
#   * A listed path that is not a tracked *.sh file also FAILS the gate (a
#     rename must not silently carry its exemption with it).
#   * Protected CI compares this list to the PR base (or main's parent) and
#     rejects every added entry, even if it is still dirty. The only explicit
#     bootstrap is the first commit that introduces this file, which has no
#     predecessor to compare; current-finding and non-vacuity checks still run.
#
